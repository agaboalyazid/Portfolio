SQL Server Data Warehouse

A three-layer warehouse that turns raw exports from two source systems into clean, analytics-ready tables.

01Overview

Customer, product and sales data came from two systems, CRM and ERP, with inconsistent codes, duplicate customer records, invalid dates and sales values that did not match quantity × price. The warehouse cleans and models the data in three layers inside SQL Server.

02Data sources

SystemFileContents
CRMcust_info.csvCustomers: names, marital status, gender, create date
CRMprd_info.csvProducts: key, cost, product line, start date
CRMsales_details.csvOrder lines: dates, quantity, price, sales
ERPCUST_AZ12.csvCustomer birthdate and gender
ERPLOC_A101.csvCustomer country
ERPPX_CAT_G1V2.csvProduct categories and maintenance flag

03What I built

  • T-SQL stored procedures that load the six CSV sources into Bronze tables (TRUNCATE + BULK INSERT), with load timing and TRY/CATCH error handling
  • Silver-layer cleaning: latest-record de-duplication with ROW_NUMBER, code decoding, date fixes, sales and price recalculation, country normalisation
  • A Gold layer of star-schema views: customer and product dimensions and a sales fact
  • Quality-check scripts, a data catalog, naming conventions, and architecture, data-flow and data-model diagrams

05Data quality checks

The Silver tables are checked with test/quality_checks_silver.sql. Each query is written so that a correct table returns no rows.

CheckExpected result
Null or duplicate primary keysNo rows
Unwanted spaces in text fieldsNo rows
Null or negative product costNo rows
Order date after ship or due dateNo rows
Sales ≠ quantity × priceNo rows
Birthdates out of rangeBetween 1924-01-01 and today

06Code excerpt

SELECT *,
    ROW_NUMBER() OVER (PARTITION BY cst_id
                       ORDER BY cst_create_date DESC) AS flag_last
FROM bronze.crm_cust_info
WHERE cst_id IS NOT NULL
-- keep flag_last = 1: the most recent record per customer
